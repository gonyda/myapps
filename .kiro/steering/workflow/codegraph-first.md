# CodeGraph 우선 원칙

## 규칙: 기존 소스 분석은 반드시 CodeGraph MCP를 최우선으로 사용합니다

기존 코드의 구조·동작·호출관계·심볼 파악은 파일을 직접 read하지 말고
**무조건 CodeGraph MCP를 먼저** 사용합니다. 기본 도구는 `codegraph_explore`
하나로, 한 번의 호출로 관련 심볼의 소스 본문 + 심볼 간 호출 경로(call path) +
영향 범위(blast radius)를 함께 돌려줍니다. "X가 어떻게 동작하나", "X가 Y까지
어떻게 도달하나", 특정 영역 훑어보기 등 대부분의 구조 질의를 이 도구로 해결합니다.
(필요 시 `codegraph_node`/`search`/`callers`/`callees`/`impact` 등도 활용 가능하나,
그 결과는 대개 `codegraph_explore` 응답에 이미 포함됩니다.)

이 규칙은 서브에이전트 컨텍스트 수집 시에도 동일하게 적용됩니다
(컨텍스트 수집은 예외가 아님).

## 이유
- **크레딧 절약**: 직접 파일 읽기는 토큰 소모가 크므로, 그래프로 필요한
  부분만 정밀하게 가져와 비용을 최소화합니다.
- `codegraph_explore`가 보여주는 소스 본문은 호출 시점에 디스크에서 다시 읽어
  주므로, 그래프를 거쳐도 코드 본문 자체는 항상 최신입니다.

## 직접 read가 허용되는 경우 (폐쇄 목록 — 이 외 전부 금지)
1. CodeGraph로 조회했으나 결과가 불충분한 경우 (최후의 수단)
2. **응답에 ⚠️ staleness 배너가 뜬 파일** — CodeGraph는 파일 변경을 FSEvents
   워처로 감지해 자동 동기화(기본 디바운스 ~2초)하지만, 방금 수정한 직후의 짧은
   창에서는 그래프 구조(호출관계·엣지 등)가 잠깐 stale일 수 있습니다. 이때 응답이
   해당 파일을 pending으로 표시하며 "직접 Read하라"는 배너를 붙이므로, 그 경우에만
   직접 read가 정당합니다. (배너가 없으면 그래프는 최신으로 간주)
3. 소스가 아닌 파일 (`.json`, `.yml`, `.xml`, `pom.xml` 등)

## 적용 범위
- 기존 소스 확인/분석 모든 작업에 예외 없이 적용됩니다.
