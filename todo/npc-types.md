# NPC 타입(시설/역할) 정의 — TODO

myrpg NPC는 **인물(individual)** 과 **타입(type)** 두 축으로 관리한다.

- **멘트(대사)**: 인물별로 관리 (원작 특유의 성격/말투 유지) → `docs/npc-dialogue.json`
- **타입**: 기능 분류용. 화면 버튼 라벨 표시 + 향후 타입별 상호작용 버튼(상점/수리 등)의 기준

버튼 라벨은 `이름 + (타입 표시명)` 형식으로 조합한다. 예: `네리스 (대장간)`

---

## 1. 타입 목록

| 타입 키 | 표시명 | 소속 NPC | 상호작용 버튼 |
|---|---|---|---|
| `chief` | 촌장 | 던컨(티르코네일) | 퀘스트 |
| `blacksmith` | 대장간 | 퍼거스(티르코네일), 네리스(던바튼) | 상점, 수리 |
| `magic-school` | 마법학교 | 라사(티르코네일), 스튜어트(던바튼) | 상점 |
| `school` | 학교 | 레이널드(티르코네일), 아란웬(던바튼) | 상점 |
| `healer` | 힐러집 | 딜리스(티르코네일), 마누스(던바튼) | 상점, 치료 |
| `bank` | 은행 | 오스틴(던바튼) | 아이템 보관, 골드 입/출금 |

> 타입 추가 시 이 표에 행만 늘리면 된다. 표시명 매핑(`chief→촌장`)은 데이터/코드 한 곳에서만 관리.

## 2. 타입별 상호작용 버튼

### 화면 배치 & 동작

- NPC 상호작용 버튼(`네리스 (대장간)` 등)을 누르면 → NPC 멘트 칸(`.npc-talk`)에 대사가 출력된다.
- 그와 함께 **NPC 멘트 칸 맨 아래에 타입별 행동 버튼이 가로로** 나열된다. (작은 크기)
- 예시 (퍼거스 = 대장간):

  ```
  =========================
   [NPC 멘트]
   수리가 실패했네~ 어쩌구~

              [상점] [수리]   ← 가로 배치, 작게
  =========================
  ```

- **1차 구현 범위**: 각 버튼 클릭 시 실제 기능 대신 `alert`로 "구현 예정입니다" 안내창만 띄운다.
- 실제 기능(상점/수리/보관 등)은 각각 별도 스펙에서 진행.

### 타입별 버튼 정의

| 타입 | 버튼 |
|---|---|
| `chief` (촌장) | 퀘스트 |

## 3. 데이터 모델 초안 (참고)

NPC 한 명은 아래와 같은 형태를 가진다. (실제 파일/스키마는 스펙 단계에서 확정)

```json
{
  "id": "neris",
  "name": "네리스",
  "type": "blacksmith",
  "nodeId": "dunbarton"
}
```

- `type` → 표시명 매핑으로 버튼 라벨 `네리스 (대장간)` 생성
- 멘트는 인물 id(`neris`) 기준으로 `npc-dialogue`에서 조회
- 멘트 선택은 **시간대(timeOfDay) 기반**: `default` 풀 + `byTime[현재 시간대]`를 병합해 랜덤 (계절 미사용, `docs/npc-dialogue.json` 참고)

## 4. 미확정 / 추후 결정
- NPC 데이터 저장 위치: 고정 데이터이므로 `resources/data/npc.json` 형태 예상 (map.json/ambience.json과 동일 방침)
- 멘트 파일 분리 기준: NPC가 늘어나면 마을/타입 단위 파일 분리 여부
- 타입별 버튼의 실제 기능 스펙(상점/수리/보관 등)은 각각 별도 스펙으로 진행
