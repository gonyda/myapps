# Memory Bank — 프로젝트 맥락 및 영속 기억 저장소

> **AI 에이전트는 교체 가능하게, 프로젝트 지식은 지속되게**
> 
> 이 메모리뱅크는 **프로젝트 맥락 저장소**입니다.
> Agent는 세션 간에 모든 기억이 초기화되므로, 이 파일들이 **유일한 연결고리**입니다.

## Memory Bank 구조

```
memory-bank/
├── activeContext.md    # 현재 작업 상태, 최근 결정사항, 다음 단계
└── memory-bank.md      # (이 파일) 메모리뱅크 개념설명 및 작성 규칙
```

## 파일 역할

### `activeContext.md` (필수)
- 현재 진행 중인 작업의 상태
- 최근 변경사항 및 결정된 설계값
- 다음 단계 및 체크포인트
- 프로젝트 전반의 패턴과 학습사항

### `memory-bank.md` (이 파일, 필수)
- 메모리뱅크 시스템의 개념과 원칙
- 갱신 규칙과 시점

## 갱신 규칙

### 갱신 시점 (자동 실행)
1. **Task/체크포인트 완료** — 진행 상태 요약의 체크박스 갱신
2. **협의 확정값 등장** — 설계값이 확정되면 즉시 기록
3. **Spec 문서 3종 완료** — 시작 전에 스펙 개요를 기록
4. **커밋/빌드 완료** — 새 커밋 해시를 최근 커밋 하이라이트에 반영
5. **다음 단계 이동 시** — 다음에 할 일을 명시

### 갱신 항목
| 항목 | 설명 |
|---|---|
| 진행 상태 요약 | 단계별 체크박스 완료/미완료 갱신 |
| 작업 트리 | 수정/신규 파일 목록(+커밋 여부) 반영 |
| 현재 스펙의 확정 설계값 | 새로 확정된 상수·규칙·수치 기록 |
| 다음 단계 | 이어서 처리할 다음 Task/체크포인트 명시 |
| 의사사항 | 스펙 문서 갱신 필요 등 후속 조치 기록 |
| 최종 업데이트 일자 | `Asia/Seoul` 기준 갱신 |

## 작업 시작 전 절차 (필수)

모든 작업(코드 작성, 리팩토링, 버그 수정, 문서 작업 포함)을 시작하기 전에 반드시:

1. `activeContext.md`를 읽는다.
2. 파일이 없거나 비어 있으면:
   - `git --no-pager log --oneline -30` 로 최근 커밋 확인
   - `git status --short` 로 미커밋 상태 확인
   - 진행 중인 spec(`.kiro/specs/`)과 관련 docs 확인
   - 위 내용으로 `activeContext.md`를 초기화한다.
