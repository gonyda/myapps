# myrpg 화면 목업 (UI Mockup)

웹 기반 솔로 RPG `myrpg`의 **메인 플레이 화면** 목업입니다.
개발 시 이 화면 구조와 CSS를 **그대로 실제 UI로 사용**합니다.

- 목업 파일: [`myrpg-mockup.html`](./myrpg-mockup.html)
- 대상: **모바일 세로(portrait) 전용**
- 방식: 순수 HTML + CSS + Vanilla JS (프레임워크 없음)

브라우저에서 `myrpg-mockup.html`을 열면 바로 확인할 수 있습니다.
(핀치 줌 등 터치 동작은 실제 모바일 또는 브라우저 개발자도구의 터치 시뮬레이션에서 확인)

---

## 1. 화면 레이아웃

세로 화면을 상단/본문/하단 3단으로 나누고, 본문은 좌측 사이드바 + 가운데 영역으로 구성합니다.

```
┌─────────────────────────────────────┐
│  상단 바 (top-bar)                    │  닉네임 / 레벨 / EXP / HP / MP / 스태미나
├──────┬──────────────────────────────┤
│ 왼쪽 │  가운데 영역 (center)          │
│ 사이 │   ├ 상황 멘트 (situation)      │  ← 4줄 높이, 넘치면 스크롤
│ 드바 │   ├ NPC 멘트 (npc-talk)        │  ← 4줄 높이, 넘치면 스크롤
│      │   ├ 상호작용 버튼 (interactions)│  ← 최소 2줄, 넘치면 스크롤
│ 장비 │   ├ 미니맵 (minimap, 3x3)       │  ← 탭하면 전체지도 팝업
│ 인벤 │   └ 이동 패드 (move-pad)        │  ← 상하좌우 화살표
│ 스킬 │                                │
│ 정보 │                                │
├──────┴──────────────────────────────┤
│  하단 행동 로그 (action-log)          │  ← 4줄 노출, 최대 10개, 넘치면 스크롤
└─────────────────────────────────────┘
```

### 컨테이너
- `.phone` : 전체 컨테이너. `max-width: 480px`, `height: 100dvh`. 데스크톱에서는 폰 크기로 중앙에 표시됩니다.

## 2. 반응형 정책 (중요)

- **세로 전용**, 모바일 우선 유동형(fluid) 레이아웃입니다.
- 크기/간격/폰트는 전부 `:root`의 CSS 변수 + `clamp()`로 화면 폭에 비례합니다. 미디어 쿼리 없이 320px~480px 폭에서 자연스럽게 조정됩니다.
- 높이가 필요한 영역은 `dvh` 기반으로 세로 화면에 맞춥니다.
- 브라우저 기본 확대/스크롤을 막기 위해 `<meta viewport>`에 `user-scalable=no`, 지도 영역에 `touch-action: none`을 사용합니다.

### 디자인 토큰 (`:root`)

| 변수 | 용도 | 값 |
|---|---|---|
| `--gap` | 요소 간 간격 | `clamp(8px, 2.6vw, 14px)` |
| `--pad` | 내부 패딩 | `clamp(10px, 3.2vw, 16px)` |
| `--radius` | 모서리 둥글기 | `clamp(6px, 1.6vw, 9px)` |
| `--fs-xs` | 아주 작은 글자 (라벨, 시간) | `clamp(9px, 2.6vw, 11px)` |
| `--fs-sm` | 작은 글자 (버튼, 로그) | `clamp(11px, 3.2vw, 13px)` |
| `--fs-md` | 본문 글자 | `clamp(13px, 3.8vw, 15px)` |
| `--fs-lg` | 제목/아이콘 | `clamp(15px, 4.6vw, 18px)` |
| `--touch` | 최소 터치 크기 | `clamp(44px, 12vw, 52px)` |
| `--bar-h` | 상태바 높이 | `clamp(9px, 2.6vw, 12px)` |

> 크기/여백을 일괄 조정하려면 이 변수 값만 바꾸면 됩니다.

### 컬러
- 배경: `#000`(바깥) / `#1a1a1a`(폰) / `#161616`~`#262626`(패널)
- 강조: EXP `#f0c419`, HP `#d9534f`, MP `#4a7bd0`, 스태미나 `#5cb85c`
- NPC 계열(초록): `#2a3a2a`, `#9ad19a`

## 3. 컴포넌트별 정리

### 3.1 상단 바 `.top-bar`
- 1행(`.top-row`): 닉네임 · 레벨 배지 · EXP 바
- 2행(`.stat-bars`): HP / MP / 스태미나 3개 바를 나란히
- 각 바는 `.bar` + 내부 `<span>`의 `width %`로 잔량 표현 (예: `.bar.hp > span { width: 80%; }`)

### 3.2 왼쪽 사이드바 `.left-sidebar`
- 버튼 4개: 장비 / 인벤토리 / 스킬 / 정보
- 클릭 시 `openPanel('제목')` 호출 → **화면을 거의 꽉 채우는 팝업**(`.panel`)이 열리고, 헤더 제목이 버튼 이름으로 표시됨
- 팝업 내부(`.panel-body`)는 현재 placeholder. 각 기능 상세 UI는 여기에 채웁니다.

### 3.3 가운데 영역 `.center`
| 영역 | 클래스 | 동작 |
|---|---|---|
| 상황 멘트 | `.situation` | 높이 `clamp(64px, 12dvh, 120px)`, 넘치면 내부 스크롤 |
| NPC 멘트 | `.npc-talk` | 상동. `.npc-name`(이름) + `<p>`(대사) |
| 상호작용 버튼 | `.interactions` | 몬스터/NPC 버튼. **최소 2줄** 노출(`max-height: touch*2+gap`), 넘치면 스크롤. 버튼 크기 고정(`flex: 0 0 ...`) |
| 미니맵 | `.minimap` | 9x5 격자 위 **그래프형 노드맵**. **가운데 칸(5열·3행)이 항상 내 위치**이고 주변만 보여줌. 연결된 자리에만 노드/간선. **탭하면 전체지도 팝업** |
| 이동 패드 | `.move-pad` | 상/하/좌/우 화살표. **PC 화살표 키 배열**(위=윗줄 가운데, 좌·하·우=아랫줄). 맵 이동용 |

- NPC 버튼은 `.npc` 클래스로 초록 계열 구분.

#### 노드맵(미니맵/전체지도) 표현 규칙 ★
실제 맵은 상하좌우에 항상 노드가 있는 게 아니라 **그래프(경로) 구조**입니다. 그래서 격자를 꽉 채우지 않고, 아래 규칙으로 표현합니다.

- **노드 배치**: 격자(`grid`) 위에서 노드가 존재하는 칸에만 `.node`를 두고, 위치는 `grid-column` / `grid-row`(맵 좌표)로 지정. 빈 칸은 비워둡니다.
- **간선(연결선)**: 노드에 방향 클래스를 붙여 이어진 방향으로만 선을 그립니다.
  - `link-right` : 오른쪽 이웃과 연결 (가로선, `::after`)
  - `link-down` : 아래쪽 이웃과 연결 (세로선, `::before`)
- **중복 방지 규칙**: 세로/가로 간선은 항상 **위쪽/왼쪽 노드에서 아래/오른쪽으로만** 그립니다. (위·왼쪽 방향 연결은 반대편 노드의 `link-down`/`link-right`로 표현되므로 `link-up`/`link-left`는 불필요)
- 간선은 이웃 노드 중심까지 닿도록 길이를 `calc(100% + gap)`으로 계산합니다.

> 데이터 연동 시: 노드 = 맵 좌표(col,row), 간선 = 인접 노드 연결 정보. 서버가 이 좌표/연결을 내려주면 그대로 클래스·인라인 스타일로 렌더링하면 됩니다.

##### 미니맵: 내 위치 중심 창(viewport window) 방식 ★
미니맵은 맵 전체가 아니라 **내 위치 주변만** 보여주는 고정 크기 창입니다.

- 미니맵은 **9x5 고정**, **가운데 칸(5열·3행)이 항상 내 위치**(`.current`)
- 내 절대 좌표 `(px, py)`를 기준으로, 각 셀의 오프셋 `(dx, dy)`(dx: -4~+4, dy: -2~+2)를 절대 좌표 `(px+dx, py+dy)`로 변환
- 해당 절대 좌표에 노드가 있으면 그 셀(`grid-column: 5+dx`, `grid-row: 3+dy`)에 렌더링, 없으면 빈 칸
- 간선은 **두 노드가 모두 창 안에 있고 실제로 연결**된 경우에만 표시
- 맵 가장자리에서도 규칙 동일 — 범위 밖은 그냥 빈 칸이라 예외 처리 불필요
- 효과: 이동하면 지도가 흐르듯 스크롤되고 항상 내 주변만 깔끔하게 노출

> 전체지도 팝업은 반대로 맵 전체를 큰 격자에 그리고 줌/팬으로 탐색합니다.

### 3.4 하단 행동 로그 `.action-log`
- **4줄 노출**, 넘치면 스크롤. 높이는 한 줄 높이 × 4 + 여백으로 계산.
- **최대 10개** 로그 유지 (초과 시 오래된 로그 제거 — 실제 구현에서 처리)
- 각 줄 구조: `.log-line` > `.log-time`(왼쪽, 회색 `YYYY-MM-DD HH:MM`) + `.log-msg`(메시지)
- `.log-time`은 `tabular-nums`로 숫자 폭 고정 정렬, 안 줄어듦(`flex-shrink: 0`)

## 4. 팝업

### 4.1 좌측 메뉴 팝업 `.panel` (`#panelOverlay`)
- 장비/인벤토리/스킬/정보 공용. 화면을 거의 꽉 채움.
- 구조: `.panel-header`(제목 + ✕) + `.panel-body`(스크롤 콘텐츠)
- API: `openPanel(title)` / `closePanel()`

### 4.2 전체지도 팝업 `.map-popup` (`#mapOverlay`)
- 미니맵 탭 시 열림. 세로 화면 **가운데에 위치**하는 모달(`88% 폭 / 최대 400px / 70dvh 높이`).
- 내용은 미니맵과 동일한 **그래프형 노드맵**(위 "노드맵 표현 규칙" 참고). 미니맵은 현재 위치 주변 일부, 전체지도는 맵 전체를 넓게 보여주는 개념이며, 큰 격자를 줌/이동으로 탐색합니다.
- **지도 앱처럼 줌/이동 지원**:
  - 모바일: 한 손가락 드래그 = 이동(팬), 두 손가락 = 핀치 줌
  - 데스크톱: 마우스 드래그 = 이동, 휠 = 커서 기준 줌
  - 우하단 `+` / `−` 버튼 = 중앙 기준 줌
- 줌 배율 제한: `0.5x ~ 4x` (`MIN_SCALE` / `MAX_SCALE`)
- 열 때 지도를 뷰포트 가운데로 자동 정렬(`resetMapView`)

#### 구현 구조
- `.map-body`(#mapViewport): 뷰포트. `overflow: hidden` + `touch-action: none`
- `.map-canvas`(#mapCanvas): 실제 이동/확대되는 레이어. `transform: translate() scale()`로 제어 (`transform-origin: 0 0`)
- 줌 수식: 지정한 점 `(px, py)`(뷰포트 기준)이 확대 후에도 같은 콘텐츠 지점을 가리키도록 translate 보정

#### JS API
| 함수 | 설명 |
|---|---|
| `openMap()` / `closeMap()` | 지도 팝업 열기/닫기 |
| `mapZoom(factor)` | 뷰포트 중앙 기준 줌 (예: `1.25` 확대, `0.8` 축소) |
| `zoomAt(factor, px, py)` | 특정 점 기준 줌 |
| `resetMapView()` | 배율 1, 지도를 뷰포트 중앙 정렬 |

> ⚠️ `.map-canvas`는 `position: absolute`라 부모 높이에 기여하지 않습니다. 그래서 `.map-popup`에는 **반드시 명시적 높이**(`height: 70dvh`)가 필요합니다. `max-height`만 주면 팝업이 헤더만 남고 접힙니다.

## 5. 실제 개발 연동 가이드

이 목업은 그대로 실제 UI로 사용합니다. 스택은 Spring Boot 4.0 + Thymeleaf(서버사이드 템플릿)입니다.

권장 이관 방식:
1. **CSS 분리**: `<style>` 내용을 `src/main/resources/static/css/`의 스타일시트로 그대로 이동. 디자인 토큰(`:root`)은 유지.
2. **HTML → Thymeleaf 템플릿**: `src/main/resources/templates/`로 이동하고, 아래 더미 데이터를 서버 모델로 치환
   - 상단 바: 닉네임/레벨/EXP·HP·MP·스태미나 % (캐릭터 진행상황 DB에서)
   - 상황 멘트 / NPC 멘트 / 상호작용 버튼 / 미니맵 노드: 현재 맵 노드 데이터(JSON)에서
   - 행동 로그: 최근 10개
3. **JS 분리**: 지도 줌/이동 스크립트를 `static/js/`로 이동.
4. **고정 데이터(맵/몬스터/아이템)** 는 JSON으로 관리, **캐릭터 진행상황** 만 DB에 저장하는 방침에 맞춰 바인딩.

### 데이터로 채워야 할 자리 (placeholder)
- 왼쪽 팝업(`.panel-body`): 장비 슬롯 배치 / 인벤토리 그리드 / 스킬 목록 / 캐릭터 정보 — **상세 미정**
- 상태 바 잔량: 하드코딩된 `width %` → 실제 수치 바인딩
- 미니맵/전체지도 노드: 하드코딩된 노드/간선 → 맵 데이터 기반 렌더링. 각 노드의 `grid-column`/`grid-row`(좌표)와 `link-right`/`link-down`(연결)을 서버 맵 데이터로 생성. 현재 위치는 `.current`, 이후 방문 여부/미탐색 등 상태별 클래스 확장 가능
- 행동 로그 시간/내용: 실제 이벤트 로그 바인딩, 최대 10개 유지 및 정렬 정책 결정

## 6. 미확정 / 추후 결정 사항
- 왼쪽 4개 팝업의 상세 내부 UI
- 행동 로그 정렬 방향(최신이 위 vs 아래) 및 자동 스크롤 여부
- NPC 멘트 칸: NPC 없을 때 숨김 vs 항상 표시
- 노드 상태 시각화 확장(방문/미탐색/이벤트 있음 등) 및 대각선 연결 허용 여부
- 맵 이동 방식 확정(화살표 4방향 / 노드 직접 선택 등)
