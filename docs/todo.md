### 7순위 메모 — 아이템 판매가 가중치

- 4순위에서 판매가 모델을 확정했고, **실제 값은 7순위(상점)에서 확정**한다.
- 판매가 공식: `sellValue = baseValue(옵션) + 총보너스포인트 × WEIGHT` (모든 보너스 스탯 **동일 가중치** `WEIGHT` 1개).
- 확정 필요 항목: `WEIGHT` 상수값, (적용 시)판매 비율, 포션 등 소비형 `baseValue`, 구매가(`buyPrice`) 실제 값.
- 예: `WEIGHT=10`이면 초보자용 한손검(STR+5) 판매가 = 50골드.

### 내구도(Durability) 이월 메모

- 모델은 4순위에서 확정: 장비만 보유, `maxDurability`(초보자 장비 20 고정) + `currentDurability`(인스턴스), **공격 턴당 장착 장비 0.2 감소**(20÷0.2 = 100턴에 0). 4순위에선 필드·초기화·표시까지만.
- **6순위(전투)**: 턴 처리 API에서 장착 장비 `reduceDurability(0.2)` 수행.
- **7순위(대장간)**: 내구도 수리(`repairToMax`) + 수리비 정책(골드 소모).
- **추후 설계**: **내구도 0 도달 시 동작**(파손 → 스탯 보너스 미적용/자동 해제/그대로 등) 확정 필요.

### 인챈트(Enchant) 이월 메모

- 4순위에서 `ItemType` 확장 지점만 열어둠(`ENCHANT`). 아직 미설계.
- 인챈트 시 **아이템 인스턴스(`OwnedItem`)에 보너스가 붙음** → 장비 보너스 합산·판매가 계산이 인스턴스 보너스를 포함하도록 이미 설계됨(그래서 판매가는 저장 안 하고 계산).
- **추후 설계 필요**: 인챈트 부여 방법(NPC/재료), 인스턴스 보너스 저장 구조, 성공/실패·비용, `ENCHANT` 타입 세부 스펙.
- 5순위(`monster-system.md`)에서 **보스 몬스터의 인챈트 아이템 드랍 자리(`itemDrops`)만 열어둠** — 실제 데이터는 인챈트 스펙 확정 후 투입.

### 5순위(몬스터) 이월 메모

- 몬스터 시스템(`monster-system.md`, 개발 완료 후 삭제 예정)에서 5순위 범위 밖으로 미룬 항목 요약.
- 5순위 구현 범위: 카탈로그(`monster.json`)·맵 매핑(`map.json` `monsters`)·조우 버튼/대사·`전투` 버튼(alert)·가위바위보 AI(정책+테스트)·드랍 계산(정책+테스트)·선공 판정(5% 서버, alert 신호까지).

**6순위(전투)로 이월**
- 실제 전투 턴 처리(가위바위보 데미지·선후공·사망). 몬스터는 스킬 없이 `SkillType` 일반34/강33/방어33 발동(`MonsterAiService.nextAction()` 소비).
- 몬스터 선공: `MonsterEncounterService.rollPreemptiveStrike`가 필드 진입 5%(전 맵 고정) 발동 시 선공 몬스터 반환. 지금은 `alert("몬스터 선공 발동")`만 → 실제 전투 진입(`POST /battle/start`, 몬스터 선공권)으로 교체.
- 드랍 지급: `MonsterRewardService.rollDrop`(골드+아이템) 결과를 처치 시 실제 지급 → `CharacterProgress.gainGold()` + 인벤토리 획득 API(`InventoryService.acquire`, 용량 30 초과 처리 포함) 신설 필요.
- `CharacterProgress` HP 감소 메서드(`damageHp` 등) 신설 — 현재 회복(`fullRecover`)만 존재.
- 처치 시 `SkillService.onSkillKill(characterId, skillId)` 호출로 스킬 킬 카운트 반영.
- 임시 골드 버튼(`/gold/gain`·`/gold/spend` + 사이드바 2버튼 + JS 2함수) 제거 — 실제 골드 획득 경로(드랍)가 열리는 시점.
- 크리티컬 실제 배율·판정 규칙 확정(몬스터 `critical`, 플레이어와 같은 0.1% 단위 정수).
- 장착 장비 내구도 턴당 0.2 감소 호출(내구도 이월 메모와 동일 지점).

**드랍 아이템 획득 시 인벤토리 초과 처리(6순위 확정)**
- 인벤토리 30칸 초과 시 동작: 획득 실패 / 자동 은행 이동 / 바닥 드랍 중 정책 확정.

**인챈트 시스템 확정 후**
- 보스 몬스터 실데이터 투입 + 보스 인챈트 아이템 드랍(`itemDrops`에 인챈트 계열). 현재는 구조만 열어둠(포션 등 기존 아이템 드랍은 가능).

**확정 (추가 설계 불필요)**
- 행동 확률 34/33/33 고정 — 몬스터별 override 없음.
- 리스폰/스폰 수량 없음 — 정적·상주(처치해도 맵에 그대로 유지).

**10순위(던전)로 이월**
- 던전 내부 몬스터 출현.

**추후 기능 — 보스 랜덤 등장 (필드)**
- 보스를 마을/던전이 아닌 **필드에 랜덤(랜덤 시간 + 랜덤 필드)** 으로 등장시키는 기능.
- **`Monster` sealed 승격 불필요** — 랜덤 등장은 데이터 형태가 아니라 **스폰 시점/위치(배치)** 문제. 보스 데이터 필드는 일반 몬스터와 동일하다.
- 필요한 것: 스폰 설정(대상 보스, 등장 확률/주기, 대상 필드 풀, 유지/소멸 시간) + 동적 배치 서비스 + **런타임 스폰 상태**(정적 로스터와 달리 상태 보관 필요, `map.json` 정적 매핑과 별개 경로).
- sealed는 보스가 **구조적으로 다른 필드**(페이즈별 스탯, 인레이지 타이머, 쫄몹 소환 등)를 가질 때만 검토 — 그런 요구가 실제로 생기면 그때 승격.
