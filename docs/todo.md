## 우선순위 근거

- **기본 시스템 행동(1위)을 최우선으로 둔 이유**: 레벨·스탯·경험치·환생은 다른 모든 시스템(스킬 랭크업 스탯, 전투 데미지 계산)의 기반입니다. 데이터 모델(`CharacterProgress`/`Stats`/`Vital`/`ExperiencePolicy`)은 001에서 이미 마련되어 있으나, 경험치 획득·레벨업·환생 **행동 로직은 전혀 없으므로** 이를 채우는 것이 1순위입니다. `accumulatedLevel` 필드는 환생용으로 예약만 되어 있습니다.
- **재능 → 스킬 순서**: 스킬은 특정 재능에 소속되는 구조(스킬이 재능을 참조)이므로, 상위 분류인 재능을 먼저 정의해야 스킬을 소속시킬 수 있습니다.
- **재화·아이템을 스킬과 몬스터 사이에 배치한 이유**: 몬스터 드랍(6위), 전투(7위), NPC 상점/수리/보관(8위), UI 인벤토리/장비 팝업(10위)이 모두 아이템·골드를 전제합니다. 이들을 먼저 정의하지 않으면 후속 시스템이 붙을 곳이 없습니다. `CharacterProgress`에는 현재 `gold` 필드나 인벤토리 연관이 없어 신규 영속 모델이 필요합니다.
- **몬스터 → 전투 순서**: 전투 시스템은 재능·스킬·몬스터·아이템 데이터에 모두 의존하므로 이들을 먼저 정의한 뒤 전투를 붙입니다. 사망/부활 처리도 전투와 함께 정의합니다.
- **NPC 행동 실기능(8위)**: 002에서 상점/수리/치료/보관/은행/퀘스트 버튼은 `alert` placeholder로만 노출됩니다. 아이템·골드·전투가 갖춰진 뒤 실제 기능을 연결합니다.
- **퀘스트(9위)**: 촌장 "퀘스트" 버튼이 이미 노출되어 있으나 기능이 없습니다. 이동·전투·아이템·NPC가 갖춰진 뒤 상위 목표 시스템으로 얹습니다.
- **UI 레이아웃(10위)**: 코어 로직과 병행 가능하지만, 장비/인벤/스킬 팝업이 아이템·스킬 시스템에 의존하므로 그 뒤에 배치했습니다.
- **던전(11위)**: 이동·전투·몬스터·맵·보상이 모두 완성된 뒤 얹히는 상위 기능이라 마지막에 두었습니다.

## 논의 필요 항목 (상세 문서 작성 시 결정)

- **기본 시스템 행동**: 경험치 획득 수단(전투가 7위이므로 그 전까지 임시 획득 수단/디버그가 필요한지), 경험치 곡선(현재 `level*100` 선형 placeholder를 어떤 곡선으로 교체할지), 환생 규칙(누적레벨 처리, 초기화 범위, 보상), 레벨업 시 재능별 보너스 스탯을 1위에서 재능 확장 가능하게 설계할지 vs 재능(2위) 도입 시 확장할지.
- **재능 시스템**: 활/마법의 장단점 설계, 재능 추가 여부, 레벨업 시 재능별 보너스 스탯 기여 방식.
- **재화·아이템**: `gold` 필드를 `CharacterProgress`에 추가할지 별도 지갑 엔티티로 분리할지, 아이템/인벤토리/장비를 신규 연관 엔티티로 어떻게 영속화할지(001이 마련한 안정적 PK 확장 지점 활용).
- **전투 시스템**: 턴마다 캐릭터·몬스터 상태 저장 방식, 데미지 배율 vs 별도 공식, 사망 시 패널티와 부활 지점.
- **퀘스트 시스템**: 퀘스트 정의(고정 JSON) 방식, 진행 상태 영속화, 보상 지급 흐름.
- **던전**: 미탐색 방을 지도에서 숨기는 UI 처리 방식, 던전 내부 몬스터/보스 배치와 전투·보상 연계.

## 저장(영속) 범위 메모

- 001 기준 DB에는 **캐릭터 진행상황(`CharacterProgress`)만** 저장하며, 고정 데이터(맵/상황 멘트/NPC)는 클래스패스 JSON 리소스에서 로드합니다.
- 아래 신규 시스템은 진행상황 성격의 데이터를 새로 저장해야 하므로, 각 스펙에서 신규 연관 엔티티(또는 필드) 추가를 명시합니다: 골드, 인벤토리/장착 장비, 습득 스킬, 재능 선택, 퀘스트 진행, 전투 상태.
- 아이템/스킬/몬스터/퀘스트의 **정의(카탈로그)** 는 고정 데이터이므로 JSON 리소스로 관리하고, 플레이어가 보유·진행한 **인스턴스/상태** 만 DB에 저장하는 001의 분리 원칙을 유지합니다.
