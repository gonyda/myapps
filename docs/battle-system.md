# 전투 시스템 상세 설계 (6순위)

> 이 문서는 `docs/todo.md` 규칙에 따라 **개발 완료 후 삭제**한다.
> 스펙 폴더는 규칙(`spec-conventions`)상 `.kiro/specs/myrpg/008-battle-system` 로 생성될 예정이다(007까지 존재).

전투는 **가위바위보(일반 / 강 / 방어) 기반 턴제**다. 플레이어는 보유 스킬 버튼을 눌러 행동하고,
몬스터는 AI가 세 행동 중 하나를 낸다. 매 턴 서버가 데미지를 계산해 **활동 로그 2줄**(내 공격 / 몬스터 공격)로 돌려준다.

## ✅ 결정 이력 (모든 항목 확정 완료)

아래는 설계 과정에서 논의·확정한 이력이다. **전 항목 확정 → 본문 반영 완료**(취소선 = 확정). 남은 것은 밸런싱 튜닝값(재능계수·몬스터 배율·크리티컬 배율·데미지 편차폭·몬스터 방어 상수 등)뿐이며 구현·밸런싱 단계에서 미세 조정한다.

### (가) 논의가 필요하다고 직접 표시한 것

1. ~~활 / 마법 재능의 전투 도입 (장단점 설계)~~ — **[확정]** 활 = **1턴 선제 사격**(DEX, 계수 소폭↓·크리티컬↑), 마법 = **고화력 + 10% 캐스팅 실패**(INT). §2.7에 반영 완료.
2. ~~몬스터 전투 HP 보관 방식~~ — **[확정] DB 영속.** 브라우저를 닫았다 재접속해도 같은 노드·같은 몬스터 HP로 전투 재개. 몬스터 HP를 **매 턴 DB 저장**. 본문 §3·§4·§5·§6에 반영 완료.
3. ~~전투 턴 중 무기 교체 허용 여부~~ — **[확정] 허용, 턴 소모 없음.** 포션과 동일한 인벤토리 탭 시스템(즉시 교체, 몬스터 행동 없음). 본문 반영 완료.

### (나) 전투 수치·규칙

4. ~~일반이 강을 이길 때(N>H) 처리~~ — **[확정]** 승자 일반 100%, 패자(강) 0(강공격 끊김). §2.2 반영.
5. ~~강이 방어를 이길 때(H>D) 처리~~ — **[확정]** 승자 강 100%(관통), 패자(방어) 반격 0. §2.2 반영.
6. ~~플레이어 공격력 산출식~~ — **[확정]** 근접=STR / 활=DEX(계수↓) / 마법=INT(계수↑). 재능별 계수 구체값은 무기·스탯 밸런싱 튜닝값. §2.4·§2.7 반영 완료.
7. ~~방어 경감률~~ — **[확정]** 방어 스킬의 `blockRateByRank`(랭크별 경감률)를 그대로 따름(고정 10% 아님, "10%"는 예시값). §2.2·§2.4 반영.
8. ~~반격 데미지 크기~~ — **[확정]** `counterMultiplier(DefenseSkill, rank)` × 방어자 공격력. 몬스터는 상수. §2.4 반영.
9. ~~데미지 공식(플레이어+몬스터) 통합 확정~~ — **[확정] 감산형**: `max(1, floor(공격력×스킬배율%/100) − 대상.defense) × 상성계수 × 크리티컬`. 최소 데미지 1 보장. 재능계수(근접1.0/활0.85/마법1.2)·몬스터 배율(일반100/강150)·크리티컬 배율(1.5)은 현재값 채택(튜닝). §2.4 반영.
10. ~~크리티컬 판정·적용범위~~ — **[확정]** 판정 `random.nextInt(1000) < critical`(0.1% 단위), **모든 결과에 적용(공격·방어·무승부)**. 배율 1.5배(튜닝값). §2.5 반영.
11. ~~양쪽 다 피해를 주는 턴의 선후공~~ — **[확정]** 일반↔방어(방어 승)일 때 **일반(공격자)의 경감된 피해 먼저 → 방어자 반격** 순서(결정론적). 동일 타입 무승부는 50:50. §2.3 반영.
11-a. ~~데미지 편차~~ — **[확정]** 상성·크리티컬까지 끝난 최종 데미지에 **±10% 균등 랜덤** 적용(최소 1 유지). §2.4·§2.5 반영.

### (다) 부가 규칙

12. ~~MP(자원) 소모~~ — **[확정]** 스킬이 정의한 자원 소모(근접/활=스태미나, 마법=MP). 마법은 캐스팅 실패해도 소모. §2.7 반영 완료. (자원 부족 시 해당 스킬 버튼 비활성 등 UI 세부는 구현 시 확정.)
12-a. ~~자원 부족 시 처리~~ — **[확정]** 부족 시 스킬 버튼 클릭하면 턴 미진행 + `alert("MP가 부족합니다!")`(마법) / `alert("스태미나가 부족합니다!")`(근접·활). §5.1·§6 반영.
13. ~~사망 → 부활 흐름~~ — **[확정]** 경험치 −10%(`applyDeathPenalty`) + HP/MP/스태미나 풀 회복 + **티르코네일 리스폰**(강제 노드 이동) + 골드·아이템 손실 없음. §4.2·§5 반영.
14. ~~도망(Escape) 기능~~ — **[확정]** 전투 화면에 **도망 버튼 상시 노출**, 성공 **50%**. 실패 시 턴 소모 + 몬스터 일방 1대 피격(전투 계속). 성공 시 전투 종료. §5·§6 반영.
15. ~~인벤토리 30칸 초과 시 드랍 처리~~ — **[확정]** 획득 실패(아이템 소실), 로그 `{아이템명} 획득 실패!`. 골드는 정상 획득. §5.2·§6.2 반영.
16. ~~내구도 0 도달 시 동작~~ — **[확정]** 자동 장착 해제(unequip). 보너스 소멸, 이후 7순위 대장간 수리 후 재장착. §5 반영.
17. ~~전투 스킬 노출 규칙~~ — **[확정]** 전투 스킬 = **착용 무기의 재능 스킬 + 공통 스킬**만 표시(예: 활 착용 → 활 재능 스킬 + 공통(방어 등)). 무기 교체(턴 무소모) 시 목록 즉시 갱신. §2.7·§6 반영.
17-a. ~~무기 재능 ≠ 캐릭터 재능일 때 특성 기준~~ — **[확정] 착용 무기 재능 기준**(활을 끼면 활 스킬만 쓰므로 특성도 무기 재능을 따름). 단 주스탯은 캐릭터가 키운 값 사용 → 재능 불일치 시 약함(자연 페널티). §2.4·§2.7 반영.

## ✅ 결정사항

### 이번 범위(6순위)에서 하는 것

- 가위바위보 전투 상태 머신: 전투 시작(`POST /battle/start`) → 턴 진행(`POST /battle/turn`) → 승리/패배 종료.
- 세 행동(일반/강/방어) 상성 판정 + 9칸 데미지 매트릭스.
- 플레이어 스킬 버튼 → 스킬 타입으로 행동 결정. 몬스터는 `MonsterAiService.nextAction()` 소비.
- 재능별 특성(§2.7): 근접=STR, 활=DEX+**1턴 선제 사격**, 마법=INT 고화력+**10% 캐스팅 실패**. 스킬 정의 자원 소모(스태미나/MP).
- 선후공 판정(동일 타입 50:50, 선공 처치 시 후공 무효).
- 기습(5%): 필드 진입 시 5% 확률로 **강제 전투 돌입**(선후공과 별개 개념, §2.6).
- HP 감소(`CharacterProgress.damageHp`) 신설, HP 0 판정.
- 사망(HP 0): 경험치 −10% + HP/MP/스태미나 풀 회복 + 티르코네일 리스폰.
- 도망 버튼(성공 50%), 전투 스킬 목록 = 착용 무기 재능 스킬 + 공통 스킬.
- 내구도 0 도달 시 자동 장착 해제.
- 활동 로그 2줄 반환(스킬명·타입·피해 + 몬스터 타입·피해), 크리티컬/방어/반격/처치 로그.
- 매 턴 캐릭터 상태 저장(`saveTurn`) + **전투 상태(몬스터 현재 HP·진행)를 DB 영속** → 브라우저 종료 후 재접속 시 **전투 재개**.
- 처치 보상 지급: `MonsterRewardService.rollDrop` 결과를 골드 가산 + 인벤토리 획득 API(신설)로 적재, 경험치 지급.
- 스킬 카운트 훅 호출: `onSkillUsed`(매 사용), `onSkillKill`(막타).
- 공격 턴당 장착 장비 `reduceDurability(0.2)` 호출.
- 포션·무기 교체: 전용 버튼 없이 인벤토리 탭에서 처리(포션 횟수 무제한, 무기 교체 자유), **턴 소모 없음**, 전투 중·이동 중 어디서든.
- 전투 재개: `GET /` 진입 시 진행 중 전투가 있으면 저장된 노드·몬스터 HP로 전투 화면 복원.
- 임시 개발용 버튼 일괄 제거: 골드 버튼(`/gold/gain`·`/gold/spend`), 경험치 버튼(`/exp/up`·`/exp/down`), 승급 팝업의 횟수/처치수 임시버튼(`dev/fill-usage`·`dev/fill-kill`, `.rankup-temp-btn`). (§9-8)

### 하지 않는 것(이월)

- 보스 실데이터·인챈트 드랍(인챈트 스펙 확정 후).
- 던전 내부 전투(10순위).
- 내구도 **수리**(대장간, 7순위) — 전투에서는 파손 시 자동 장착 해제까지만.

### 확정된 규칙 (사용자 입력 기반)

- **상성**: 일반 > 강, 강 > 방어, 방어 > 일반 (순환).
- **데미지 등급**: 일반 = 평범, 강 = 높음.
- **방어가 일반공격을 이길 때**: 방어자가 받는 피해 = 들어온 일반 데미지 × (1 − 방어 스킬 `blockRateByRank` 경감률) + **반격**(`counterMultiplier` × 방어자 공격력). (경감률 90% 랭크면 10%만 피격.)
- **동일 타입끼리**: 양쪽 모두 자기 데미지의 **50%**만 입힘.
- **동일 타입 선후공**: 플레이어 / 몬스터 **50:50**.
- **선공 처치 규칙**: 선공이 후공을 먼저 죽이면 **후공 데미지는 들어가지 않음**.
- **기습(강제 전투 돌입)**: 필드 진입 시 **5% 확률로 강제 전투 시작**. 선택 조우와 달리 자동 돌입하며, **선후공과는 무관한 별개 개념**(첫 턴 순서는 일반 규칙 적용).
- **몬스터 방어(DEFENSE) 상수**: 몬스터는 스킬이 없으므로 방어 시 **경감률 기본 40% / 반격율 기본 30%(×`attackPower`)**. `monster.json`에 `defenseBlockRate`/`defenseCounterRate` per-monster 오버라이드(미지정 시 전역 기본). **보스는 60% / 50%** 권장. 둘 다 %라 전 레벨 자동 스케일.
- **디펜스 스킬 반격 하향(밸런스 패치)**: `skill.json` 디펜스 `counterMultiplierByRank`를 **마스터 100 → 50**으로 하향(경감률은 유지). 반격이 일반공격(100%)보다 항상 낮게 유지.
- **재능 — 근접**: STR 기반, 특수 기믹 없음(안정형).
- **재능 — 활**: DEX 기반, 데미지 계수 근접 대비 소폭↓·**크리티컬율↑(활 무기에서 부여)**. **1턴 선제 사격** — 첫 턴 몬스터 행동 무효 + 유저 스킬 100% 적중(방어 스킬도 반격 100%), 2턴차부터 일반 규칙. 기습으로 시작해도 1턴 선제 적용.
- **재능 — 마법**: INT 기반, **데미지 계수 높음**. 공격 마법 **10% 캐스팅 실패**(행동 무효 + 턴 소모 + MP 소모, 몬스터 방어면 양쪽 0). 방어는 재능 무관이라 실패 없음.
- **자원 소모**: 근접/활=스태미나, 마법=MP (스킬 정의값). 마법은 실패해도 MP 소모.
- **포션**: 별도 버튼 없음, 인벤토리 탭 클릭으로 **횟수 제한 없이** 사용, 이동 중에도 사용 가능(턴 소모 없음).
- **무기 교체**: 전투 턴 중에도 인벤토리 탭에서 자유 교체, **턴 소모 없음**(포션과 동일 시스템).
- **전투 상태 영속·재개**: 전투 진행 상태(몬스터 현재 HP 포함)를 매 턴 DB 저장 → 브라우저를 닫았다 다시 들어와도 **같은 전투를 이어서** 진행.
- **크리티컬**: `random.nextInt(1000) < critical`(0.1% 단위), **모든 결과에 적용**(공격·방어·무승부). 배율 1.5배(튜닝값).
- **데미지 편차**: 모든 최종 데미지(공격·반격·무승부·크리티컬 포함)에 **마지막으로 ±10% 균등 랜덤**을 곱함 → 전투 예측 불가능성. 최소 1 유지.
- **사망**: HP 0 시 경험치 −10% + HP/MP/스태미나 **풀 회복** + **티르코네일 강제 리스폰** + 골드·아이템 손실 없음.
- **도망**: 전투 화면에 도망 버튼 상시. **성공 50%** → 전투 종료. 실패 → 턴 소모 + 몬스터에게 일방 1대 피격(전투 계속).
- **드랍 인벤토리 초과**: 아이템 획득 실패(소실), 로그 `{아이템명} 획득 실패!`. 골드는 정상.
- **내구도 0**: 해당 장비 **자동 장착 해제**(보너스 소멸, 7순위 대장간 수리 후 재장착).
- **전투 스킬 노출**: **착용 무기 재능 스킬 + 공통 스킬**만 표시(무기 교체 시 즉시 갱신).

## 1. 현재 소스 분석 (as-is)

전투에 필요한 **접점(seam)은 대부분 열려 있으나, 전투를 구동하는 규칙·계산·상태는 미구현**이다.

| 영역 | 이미 있음 | 미구현(신설 대상) |
|---|---|---|
| 조우/진입 | `PlayScreenController.encounterMonster` (`POST /monster/encounter`), `monster-response.html`, center의 `monster-actions` 버튼, `myrpg.js.monsterAction()`(현재 `alert("구현 예정입니다")`) | `POST /battle/start`, `POST /battle/turn` |
| 기습(강제 전투 돌입) | `MonsterEncounterService.rollPreemptiveStrike(List<Monster>)` 5% 판정, `move()`에서 호출 → `alert("몬스터 선공 발동")` 신호까지. **실제 의미는 "필드 진입 시 강제 전투 돌입"**(선후공 아님) | 5% 발동 시 자동 `battle/start`(강제 전투 진입). 명칭 `ambush` 계열로 정리 권장 |
| 몬스터 AI | `MonsterAiService.nextAction()` → `SkillType`(34/33/33) | AI 결과를 데미지로 소비 |
| 스킬 수치 | `SkillDamagePolicy.multiplier/blockRate/counterMultiplier`(랭크→% 조회), `DamageSkill`/`DefenseSkill`(`sealed Skill`) | RPS 승패 배율·최종 데미지 공식 |
| 스킬 카운트 | `SkillService.onSkillUsed`/`onSkillKill` (임시 드라이버가 대체 중) | 전투에서의 실제 호출 |
| 캐릭터 상태 | `CharacterProgress` (`hpCurrent` 등), `fullRecover`, `gainGold`; `StatProgression.levelStatsFor`, 장비 보너스 `InventoryService.equippedBonus`, 스킬 랭크 보너스 | **`damageHp` 없음**, 사망/부활 없음, `attackPower` 단일값 없음 |
| 사망 | `ProgressionService.applyDeathPenalty` → `DeathResult(experienceLost)` (경험치 −10%) | HP0 판정·부활 |
| 상태 저장 | `CharacterService.saveTurn(progress)` (이동/경험치/환생에서 호출) | 전투 턴 저장, 몬스터 HP 보관 |
| 내구도 | `OwnedItem.reduceDurability(double)`/`repairToMax`, `maxDurability`(초보자 20) | **턴당 0.2 감소 호출부 없음** |
| 보상 | `MonsterRewardService.rollDrop(Monster)` → `DropResult(gold, items)` | **인벤토리 획득 API 없음**(용량 30은 이동 시만 검사) |
| 로그 | `ActionLog.add(msg, type)`(세션 보관, 최대 10건), `ActionLogEntry(timestamp, message, type)`, `action-log.html`(type→CSS class) | 전투 턴 로그 |
| 스탯 | `Stats(str, dex, intelligence, critical, defense)` — STR/DEX/INT base 10·+3/lv, `critical` **0.1% 단위**(base 50=5%·+0.3%/lv), `defense` **정액**(base 5·+1/lv). `StatProgression`이 산출 | 스탯→공격력 매핑 |

> **주의(정합성)**: `SkillDamagePolicy`·`MonsterAiService` 일부 JavaDoc이 전투를 "7순위"로 잘못 표기한 곳이 있음. 실제 로드맵은 **6순위**. 구현 시 문구 정정.

### 몬스터 데이터 현황 (`monster.json`)

현재 `raccoon`(너구리) 1종만 존재.

```
id=raccoon, type=NORMAL, level=1, maxHp=45, attackPower=48, defense=3,
critical=30(=3.0%), experience=22, goldDrop{min=6,max=16},
itemDrops=[{hp_potion_30, 15%, 1~1}], lines=3
```

> 너구리 스탯은 **초보 풀장비(한손검+방패+갑옷+투구+장갑+부츠, 유효 DEF ~22)** 와 6~7턴 치고박는 접전이 되도록 재조정됨. 데이터 밸런싱 기준은 `data-balance-guide.md` 참조.
> (주의: 기본 seed는 한손검+방패+갑옷만 자동 장착=DEF 15이므로, 이 밸런스가 성립하려면 투구·장갑·부츠도 장착해야 함.)

`Monster` 레코드는 **불변 카탈로그**라 전투 중 현재 HP를 포함하지 않는다(→ 별도 `BattleState`에 현재 HP 보관·영속, §3). `critical`은 0.1% 단위 정수(30 = 3.0%).

## 2. 가위바위보 전투 규칙 (핵심)

### 2.1 행동 3종과 상성

| 타입 | `SkillType` | 성격 | 이김(상성) |
|---|---|---|---|
| 일반공격 | `NORMAL` | 평범한 데미지 | 강(HEAVY)을 이김 |
| 강공격 | `HEAVY` | 높은 데미지 | 방어(DEFENSE)를 이김 |
| 방어 | `DEFENSE` | 피해 경감 + 반격 | 일반(NORMAL)을 이김 |

순환: **일반 → 강 → 방어 → 일반**.

플레이어의 행동은 **누른 스킬 버튼의 타입**으로 결정된다(예: "윈드밀" = 일반). 몬스터는 스킬 없이 `nextAction()`이 타입만 반환.

### 2.2 데미지 판정 매트릭스 (9칸)

행 = 나(플레이어), 열 = 상대(몬스터). 셀 = **(내가 주는 피해 / 내가 받는 피해)**. 9칸 모두 **[확정]** (구체 데미지 수치는 §2.4 공식).

| 나 \ 상대 | 일반(N) | 강(H) | 방어(D) |
|---|---|---|---|
| **일반(N)** | 무승부: **내 일반 50% / 상대 일반 50%** | 내 승(N>H): **내 일반 100% / 상대 0** | 상대 승(D>N): **내 일반 (경감 후) / 상대 반격** |
| **강(H)** | 상대 승(N>H): **내 0 / 상대 일반 100%** | 무승부: **내 강 50% / 상대 강 50%** | 내 승(H>D): **내 강 100% / 상대 0(반격무효)** |
| **방어(D)** | 내 승(D>N): **내 반격 / 상대 일반 (경감 후)** | 상대 승(H>D): **내 0(반격무효) / 상대 강 100%** | 무승부: **양쪽 0(교착)** |

읽는 법 요약:
- **공격 vs 공격 (상성 승패)**: 이긴 쪽이 자기 데미지 100%, 진 쪽 0.
- **공격 vs 방어**:
  - 방어가 일반을 이김 → 공격자 데미지는 **방어자 경감률만큼 감소**(플레이어 방어=디펜스 스킬 `blockRateByRank`, 몬스터 방어=`defenseBlockRate` 기본 40%), 방어자는 반격.
  - 강이 방어를 이김 → 강이 100% 관통, 방어자 반격 무효.
- **동일 타입 (무승부)**: 양쪽 자기 데미지 50%. 방어↔방어는 서로 공격이 없으므로 0(교착).
- **크리티컬**: 위 모든 셀의 데미지에 크리티컬 판정 적용(§2.5).

### 2.3 선후공(턴 순서) **[확정]**

- 선후공이 결과를 바꾸는 경우는 **양쪽 모두 피해가 있는 턴뿐**이다(한쪽만 피해면 순서 무의미).
- **매 턴** 선후공을 정한다. 선공이 후공을 **먼저 죽이면 후공 피해는 적용하지 않는다**.
- **동일 타입 무승부(일반↔일반, 강↔강)**: 플레이어/몬스터 **50:50**.
- **일반↔방어(방어 승)**: **결정론적** — 공격자(일반)의 **경감된 피해**가 먼저 들어가고, 그다음 방어자가 **반격**(코인플립 없음).
- 그 외 상성 승패(강↔일반 등)는 진 쪽 피해가 0이라 순서와 무관.
- 선후공은 **기습 여부와 무관**(기습은 강제 전투 돌입일 뿐, §2.6).
- **활 재능**은 이 규칙을 **2턴차부터** 따른다 — 첫 턴은 활 전용 **"1턴 선제 사격"**(§2.7)이 우선한다.

### 2.4 데미지 공식 **[확정]** (감산형, 배율만 튜닝)

```
공격력   = round(주스탯 × 재능계수)                       // 주스탯: 착용 무기 재능별(STR/DEX/INT), 장비·스킬 보너스 포함
기본피해 = max(1, floor(공격력 × 스킬배율% / 100) − 대상.defense)
보정피해 = 기본피해 × 상성계수 × (크리티컬 ? 1.5 : 1)      // 상성 + 크리티컬
최종피해 = max(1, round(보정피해 × rand(0.90 ~ 1.10)))    // ★ ±10% 편차 — 매 타격 마지막에 적용
```

- **주스탯 × 재능계수** (§2.7·17-a): 근접=STR×1.0 / 활=DEX×0.85 / 마법=INT×1.2 (계수 튜닝값, 현재값 채택). 주스탯은 **착용 무기 재능** 기준.
- `스킬배율(%)`:
  - 플레이어: `SkillDamagePolicy.multiplier(DamageSkill, rank)` (장착 스킬 랭크 기반). "일반=평범 / 강=높음"은 스킬 배율표에서 자연 발생.
  - 몬스터: 스킬 없음 → 행동별 상수 **일반=100 / 강=150**(튜닝값). `공격력`은 `Monster.attackPower`.
- `대상.defense`: **정액 감산**. 플레이어 `Stats.defense`(+장비/스킬 보너스), 몬스터 `Monster.defense`.
- **최소 데미지 1 보장.**
- `상성계수`(§2.2): 승 1.0 / 무승부 0.5 / 방어당함 `(1 − blockRate)` / 관통패 0.0. **방어자가 플레이어면 디펜스 스킬 랭크값, 몬스터면 `defenseBlockRate`(기본 40%)**.
- **방어 반격**: 플레이어 `counterMultiplier(DefenseSkill, rank) × 공격력`(마스터 반격율 50%로 하향), 몬스터 `defenseCounterRate% × attackPower`(기본 30%).
- **크리티컬**: 모든 데미지에 판정(§2.5), 배율 1.5.
- **데미지 편차(최종 단계)**: 상성·크리티컬까지 끝난 값에 **±10% 균등 랜덤**(`× rand(0.9~1.1)`)을 마지막에 곱함 → 예측 불가능성. 매 타격마다 적용, 최소 1 유지. (크리티컬·편차는 주입 `Random`으로 계산 → 시드 고정 테스트 가능. 감산·상성 등 결정 부분은 순수 유지.)
- **재능 오버라이드(§2.7)**: 활 1턴 선제(상성 무시 100% 적중, 몬스터 0)와 마법 캐스팅 실패(행동 무효)는 이 공식보다 **우선 적용**.
- 참고(Lv1 근접 vs 너구리, 풀장비 유효 DEF 22): 공격력 = (STR 10 + 한손검 +5) × 1.0 = **15**. 윈드밀(F랭크 배율 90%) 기본피해 = `floor(15 × 0.90) − 너구리 DEF 3` = **10**. 상성계수는 양쪽에 동일하게 곱한다:
  - **내가 이기는 턴(일반>강)**: 나 10×1.0 = **10** / 너구리 **0**.
  - **무승부 턴(일반↔일반)**: 나 10×0.5 = **5** / 너구리 `(48−22)×0.5` = **13**.
  - 여기에 크리티컬(§2.5)·편차 ±10%(§2.4)가 더해져 매 턴 변동한다. 승·무·패 턴이 섞여 6~7턴 접전(`data-balance-guide.md` 기준).

> **고렙 밸런싱 가이드**: 데미지가 **정액 감산 + 최소 1**이라 자동 난이도 스케일링이 없다. 고렙/보스 몬스터는 `attackPower`를 그 구간 플레이어 DEF 위로, `maxHp`·`defense`를 플레이어 딜 성장 위로 직접 authoring해야 난이도가 유지된다. (방어 경감/반격은 %라 자동 스케일되지만, 원시 스탯 커브는 데이터 밸런싱 몫.)

### 2.5 크리티컬 **[확정]** (배율만 튜닝)

- 판정: `random.nextInt(1000) < critical` (critical=50 → 5.0%). 플레이어·몬스터 동일.
- 배율: **1.5배** (튜닝값).
- 적용 범위: **모든 결과에 적용** — 공격뿐 아니라 방어(반격)·무승부(50%) 데미지에도 크리티컬 판정.
- **순서**: 크리티컬(×1.5) 적용 후 **마지막에 ±10% 데미지 편차**가 곱해진다(§2.4).
- **활 재능은 크리티컬율이 높다** — 활 무기의 크리티컬 보너스로 부여(§2.7).

### 2.6 기습 (강제 전투 돌입) — 선후공과 별개 **[확정]**

- **기습 = 필드 진입 시 5% 확률로 강제로 전투가 시작되는 것**이다. 일반 조우(몬스터 버튼을 눌러 스스로 전투 시작)와 달리, 이동만 했는데 자동으로 전투에 돌입한다.
- **선후공(누가 먼저 때리나)과는 완전히 별개 개념.** 기습으로 시작된 전투라고 해서 몬스터가 첫 턴 선공을 갖는 것이 아니다. 첫 턴 선후공도 일반 규칙(§2.3, 기본 50:50)을 따른다.
- 판정: 기존 `MonsterEncounterService.rollPreemptiveStrike`(5%, 전 맵 고정)를 **강제 전투 돌입 판정**으로 사용한다. (메서드/필드명이 "preemptive(선공)"으로 되어 있으나 실제 의미는 기습=강제 조우이므로, 구현 시 명칭을 `ambush`/`forcedEncounter` 계열로 정리 권장.)
- 흐름: `POST /move` 결과가 이동 성공이고 그 노드에 몬스터가 있으면 5% 굴림 → 발동 시 해당 몬스터로 **자동 `battle/start`**(플레이어 선택 없이 전투 화면 진입).

### 2.7 재능별 전투 특성 (근접 / 활 / 마법) **[확정]**

**공격력 산출 (나-6 확정)**

| 재능 | 주스탯 | 데미지 계수 | 특성 |
|---|---|---|---|
| 근접(MELEE) | STR | 기준(×1.0) | 특수 기믹 없음(안정형) |
| 활(BOW) | DEX | 근접 대비 소폭↓ | 크리티컬율↑(활 무기에서 부여) + **1턴 선제 사격** |
| 마법(MAGIC) | INT | 높음(근접/활보다↑) | **10% 캐스팅 실패** 리스크 |

> 계수 구체값(근접 1.0 / 활 0.85 / 마법 1.2 채택)과 활 크리티컬 부여량은 튜닝값 — 무기·스탯 밸런싱에서 미세 조정.

> **특성 기준 = 착용 무기 재능 (17-a 확정)**: 활을 끼면 활 스킬만 쓰므로 1턴 선제·계수 등 특성도 **무기 재능**을 따른다. 단 주스탯은 캐릭터가 키운 실제 값을 쓰므로, 무기 재능 ≠ 캐릭터 재능이면 주스탯이 낮아 약해진다(자연 페널티).

**활 — 1턴 선제 사격**

- 전투 **첫 턴**, 활 유저는 무조건 선제. 몬스터의 1턴 행동은 **완전 무효**(피해·방어·반격 0).
- 유저가 낸 스킬은 **상성 무시 100% 적중**(상성계수 1.0). 강공격 vs 몬스터 일반공격이어도 유저만 피해.
- **방어 스킬을 내도 유저 피해 100%** — 방어의 반격 데미지가 100% 그대로 몬스터에게 적중.
- 크리티컬 판정 정상. **2턴차부터** 일반 규칙(RPS + 50:50).
- **기습(강제 전투)으로 시작해도 1턴 선제는 동일 적용**(기습 ≠ 몬스터 선공, §2.6).
- **발동 조건은 "활을 처음 든 턴"이 아니라 "전투 첫 턴(`turnCount == 1`)에 활이 장착돼 있을 때"다.** 즉 다른 무기로 첫 턴을 치른 뒤 활로 교체해도(§6.1 3-c) 선제는 발동하지 않는다(그 시점엔 `turnCount != 1`). 전투 중 무기 교체가 1턴 선제를 리셋하지 않는다.

**마법 — 캐스팅 실패**

- 공격 마법 스킬(일반/강) 사용 시 **10% 확률로 실패**. 방어(재능 무관 공통 스킬)는 **실패 없음**.
- 실패 시: 플레이어 행동 **완전 무효 + 턴 소모 + MP 소모**(실패해도 소모). 몬스터 행동은 정상 처리 — 공격이면 피해, **방어면 양쪽 0**.
- 판정 순서: 턴 시작 시 10% 굴림 → 실패면 RPS 계산 스킵.
- 로그: `{스킬명} 캐스팅 실패!` (예: `파이어볼트 캐스팅 실패!`).

**자원 소모 (다-12 확정)**

- 스킬이 정의한 자원을 소모: **근접/활 = 스태미나**, **마법 = MP** (`Skill`의 자원 종류/`resourceCost`, `ResourceKind`).
- 마법은 캐스팅 실패해도 MP 소모.

## 3. 전투 상태 보관 — DB 영속 (재개 지원) **[확정]**

**요구**: 브라우저를 닫았다가 다시 들어와도 **같은 노드에서 같은 몬스터와, 닫기 직전 몬스터 HP 그대로** 전투를 이어야 한다.

**결정: 전투 진행 상태를 DB에 영속화한다.** (세션 보관은 브라우저/세션 종료 시 사라져 재개 불가 → 채택하지 않음.)

- 신규 엔티티 `BattleState` (캐릭터 1:1, `characterId` 기준):
  - `monsterId`, `monsterCurrentHp`, `turnCount`, `ambush`(기습=강제 전투로 시작했는지), `active`(진행 여부).
  - 캐릭터의 `currentNodeId`는 이미 영속되므로 **전투 장소(예: 두갈드 아일 북부)는 자동 복원**된다.
- 저장 시점: 전투 시작 시 생성, **매 공격 턴 종료 시** `characterService.saveTurn(progress)`와 함께 `BattleState` 저장(**몬스터 HP 포함**).
- 종료 시점: 승리/패배/도망 시 `active=false`(또는 삭제).
- 재개: `GET /` 진입 시 `active`한 `BattleState`가 있으면, 저장된 몬스터 HP로 전투 화면을 복원한다.
- 엣지 케이스:
  - 저장된 `monsterId`가 카탈로그/노드에서 사라졌으면(데이터 변경) 전투를 안전 종료.
  - 동시에 하나의 전투만 활성(단일 캐릭터 구조: `loadOrCreateDefault`).

> **"몬스터 HP도 매 턴 저장하나?" → 그렇다.** 재개를 지원하려면 몬스터 현재 HP를 매 턴 영속해야 한다. 턴당 추가 DB 쓰기 1회는 무시할 수준.

> 대안(임베드): 별도 엔티티 대신 `CharacterProgress`에 전투 필드를 직접 추가하는 방법도 가능(더 단순). 관심사 분리를 위해 별도 `BattleState` 엔티티를 권장하되, 단순함을 우선하면 임베드도 무방 — 구현 시 택1.

## 4. 도메인 모델 (신규 / 확장)

> 하위 호환 유지: 기존 필드/시그니처는 보존하고 추가만 한다.

### 4.1 신규

- `BattleState` (JPA @Entity, 캐릭터 1:1): 진행 중 전투 상태(§3) — `monsterId`, `monsterCurrentHp`, `turnCount`, `ambush`, `active`. 매 턴 DB 영속.
- `BattleTurnResult` (record): 한 턴 결과 — 플레이어 행동/피해, 몬스터 행동/피해, 크리티컬·방어·반격 플래그, 전투 종료 여부, 승패, 드랍/경험치(종료 시).
- `RockPaperScissors` / `BattleResolver` (도메인 순수 로직): 두 `SkillType`와 수치를 받아 §2.2 매트릭스로 양측 피해를 계산하는 순수 함수(테스트 용이).

### 4.2 확장

- `CharacterProgress`:
  - `damageHp(int amount)` **신설** — `hpCurrent = max(0, hpCurrent - amount)`, 0 바닥. `isDead()` 헬퍼(`hpCurrent == 0`).
- **사망 처리 [확정]** (`ProgressionService.die()` 또는 `BattleService`에서 조합):
  - `applyDeathPenalty`(경험치 −10%, 기존) + `fullRecover(VitalMax)`(HP/MP/스태미나 풀 회복) + `updateCurrentNodeId("tir-chonaill")` 강제 이동. 골드·아이템 불변.
  - 티르코네일 리스폰 노드 id = `tir-chonaill`(map.json).

## 5. 서비스 (신규)

### 5.1 `BattleService` (application)

- `start(CharacterProgress, monsterId, ambush)` → `BattleState` 생성(몬스터 풀 HP, **`turnCount=1`**, `active=true`, `ambush` 플래그), **DB 저장**, 시작 로그. (첫 `takeTurn`이 `turnCount==1`을 보므로 활 1턴 선제(§2.7)가 첫 턴에 성립.)
- `resumeIfActive(CharacterProgress)` → `active`한 `BattleState`가 있으면 전투 뷰 복원용 상태 반환(`GET /`에서 사용, §6.1).
- `flee(CharacterProgress, BattleState)` → **50% 성공**. 성공: `active=false`(전투 종료, 노드 유지). 실패: 턴 소모 + 몬스터 1회 공격(일방 피해, `damageHp`) + `saveTurn`, 전투 계속.
- `takeTurn(CharacterProgress, BattleState, skillId)`:
  1. 스킬 조회 → 플레이어 행동 타입 결정, `MonsterAiService.nextAction()`으로 몬스터 타입 결정.
  2. **자원 검사·소모**: 자원(스태미나/MP)이 스킬 비용보다 적으면 **턴 미진행**(프런트 `alert` — MP/스태미나 부족). 충분하면 차감. **마법 캐스팅 실패(10%) 판정**(공격 마법만) — 실패 시 플레이어 행동 무효(MP는 이미 소모)로 두고 3(재능 분기)을 건너뛴 뒤, 몬스터 행동만 4~9로 정상 해결(플레이어 피해·사망 판정 포함).
  3. **재능 분기(§2.7)**: 활이고 `turnCount==1`이면 **1턴 선제 사격**(몬스터 행동 무효, 유저 스킬 100% 적중). 그 외에는 `BattleResolver`로 §2.2 매트릭스 산출(상성·크리티컬·방어·반격).
  4. 선후공 결정(§2.3) → 선공 피해 적용 → 처치 시 후공 스킵.
  5. `progress.damageHp(...)`, `battleState.monsterCurrentHp -= ...`.
  6. `SkillService.onSkillUsed(...)`; 처치 시 `onSkillKill(...)`.
  7. 공격 턴이면 장착 장비 `reduceDurability(0.2)` → **내구도 0 도달 시 자동 장착 해제(unequip)**.
  8. `characterService.saveTurn(progress)` + **`BattleState` 저장**(몬스터 HP 갱신, **턴 종료 시 `turnCount += 1`**).
  9. 몬스터 사망 → §5.3 보상 + `BattleState.active=false`. **플레이어 사망(HP 0) → 경험치 −10% + 풀 회복 + 티르코네일 리스폰(§4.2)** + `BattleState.active=false`.
  10. `BattleTurnResult` 반환.

### 5.2 `InventoryService.acquire(...)` **신설** (드랍 적재)

- `DropResult`(골드+아이템)를 소비: `progress.gainGold(gold)`(골드는 항상 획득) + 아이템별 `OwnedItem` 생성/수량 증가.
- **용량 30 초과 [확정]**: 해당 아이템 **획득 실패(소실)**, 로그 `{아이템명} 획득 실패!`. 나머지 아이템 처리는 계속.

### 5.3 보상 처리 (BattleService 내부 또는 RewardService)

- `MonsterRewardService.rollDrop(monster)` → `acquire(...)` → `progressionService.gainExperience(progress, monster.experience())`(레벨업 연쇄) → 처치/드랍 로그.

## 6. 뷰 / UI / 활동로그

### 6.1 화면 흐름

**1) 전투 진입**
- **일반 조우**: 몬스터 버튼 클릭 → `POST /monster/encounter` → `.center`의 몬스터 대사 영역(`npc-talk.active-monster`)에 **조우 대사 + `전투` 버튼** 표시. `전투` 버튼 클릭 → `POST /battle/start`.
- **기습(강제)**: `POST /move` 성공 시 5% 굴림 발동 → `alert("매복하고 있던 너구리가 기습해옵니다!")`(형식 `{몬스터명}이(가)`) 출력 후, 플레이어 선택 없이 **자동 `battle/start`**(§2.6). 이 alert가 기존 선공 `alert("몬스터 선공 발동")`을 대체한다.
- (`myrpg.js.monsterAction()`의 `alert("구현 예정")`·기존 선공 `alert` 제거)

**2) 전투 화면 레이아웃 — 전용 프래그먼트 [확정]**

전투 뷰는 **전용 프래그먼트** `templates/fragments/battle-view.html`(`th:fragment="battle-view"`)로 분리한다. `POST /battle/start`·`/battle/turn`·`/battle/flee` 응답이 이 프래그먼트를 렌더해 **`.center` 전체를 교체**한다. 전투 중에는 기존 `situation`(상황멘트)·`npc-talk`(대사)·`interactions`(조우 버튼) 영역이 사라지고 battle-view가 그 자리를 채운다.

battle-view 구성:
- **몬스터 이름 + 레벨** — 예: `너구리 Lv.1`
- **몬스터 HP 바** — `monsterCurrentHp / maxHp` (기존 `.bar`/`.fill`/`.bar-text` 오버레이 컴포넌트 재사용)
- **스킬 버튼 영역**(`#battleSkills`) = 착용 무기 재능 스킬 + 공통 스킬(§2.7·17) + **도망 버튼(상시)**. 장비 교체 시 이 영역만 실시간 재렌더(3-c).
- **미니맵** — 전투 중에도 **그대로 유지**(현재 위치 표시). battle-view가 `.center`를 통째로 교체하므로 미니맵 마크업(`fragments/minimap`)을 battle-view 프래그먼트에 **포함**한다.

프레임 유지 요소(전투 중에도 그대로 노출):
- 플레이어 게이지바(HP/MP/스태미나)·EXP는 **`.top-bar`의 `.stat-bars`에 그대로 유지**(사이드바 아님). 턴 응답에서 `.top-bar`를 함께 교체해 실시간 갱신.

**3) 턴 진행** (스킬 버튼 클릭)
- 클릭 즉시 `alert("{스킬명} 스킬을 사용하였습니다.")` 출력(예: `윈드밀 스킬을 사용하였습니다.`).
- 이어서 `POST /battle/turn`(skillId) → 서버 데미지 계산 → 응답으로 **`.top-bar`(플레이어 게이지)** + **battle-view(몬스터 HP 바·스킬 영역)** + **`.action-log`(2줄)** 를 함께 교체해 실시간 갱신.
- **자원 부족 시**: 클릭해도 턴 미진행, `alert("MP가 부족합니다!")`(마법) / `alert("스태미나가 부족합니다!")`(근접·활)만.
- **도망 버튼**: `POST /battle/flee`(성공 50%, §5.1).

**3-a) 전투 중 이동 차단 [확정]**
- `.move-pad`는 전투 중에도 **그대로 출력**한다. 단 **전투 중 이동은 불가** — 방향 버튼 클릭 시 `POST /move`를 호출하지 않고 `alert("전투 중에는 이동할 수 없습니다.")`만 띄운다.
- 구현: 클라이언트 플래그 `battleActive`(전투 시작 시 `true`, 승리/패배/도망 성공 시 `false`)를 `move(dx, dy)` 진입부에서 검사 → `true`면 alert 후 즉시 return. 방어적으로 서버 `POST /move`도 활성 전투가 있으면 이동을 거부한다.

**3-b) 포션 사용 — 실시간 반영 [확정] (턴 무소모)**
- 전투 중 인벤토리 팝업에서 포션 클릭 → `POST /inventory/use` → **턴 소모·몬스터 행동 없음**.
- 회복 결과는 즉시 **`.top-bar` 게이지(HP/MP/스태미나)** 에 실시간 반영(기존 `usePotion`의 top-bar 갱신 흐름 재사용). 몬스터 현재 HP·`turnCount` 불변.

**3-c) 장비 교체 — 실시간 반영 [확정] (턴 무소모) + 스킬 목록 실시간 변경**
- 전투 중 인벤토리 팝업에서 장비 착용/해제 → `POST /inventory/equip`·`/unequip` → **턴 소모·몬스터 행동 없음**.
- **무기를 바꾸면 전투 스킬 목록이 실시간으로 갱신된다**(§2.7·17: 착용 무기 재능 스킬 + 공통 스킬). 구현: `battleActive`일 때 equip/unequip 성공 후 JS가 스킬 서브프래그먼트를 재요청(`GET /battle/skills` → `battle-view :: battle-skills`)해 `#battleSkills` 영역만 교체.
- 무기 재능이 바뀌면 이후 턴의 재능 특성(근접/활/마법, §2.7)·주스탯 기준도 새 무기 기준으로 적용된다. 장비 스탯 변화(공격력·방어)는 다음 턴 계산에 즉시 반영.

**4) 승리** (몬스터 HP 0)
- 마지막 턴의 데미지 로그·게이지 반영 후 `alert("너구리가 쓰러졌습니다!")`.
- 활동 로그에 **보상 3줄**(골드 → 드랍 아이템 → 경험치, §6.2).
- `battleActive=false`로 전환 후 `.center`를 **현재 노드 플레이 화면으로 복원**(`buildViewFromProgress`). 몬스터는 정적·비리스폰이라 **너구리 버튼이 다시 존재**한다.

**5) 패배** (플레이어 HP 0)
- 마지막 턴의 데미지 로그·게이지 반영 후 `alert("정신을 잃고 쓰러졌습니다… 티르코네일에서 되살아납니다.")` 출력.
- **alert 확인 후** 사망 처리(§4.2) 실행: 경험치 −10% + HP/MP/스태미나 풀 회복 + 티르코네일 리스폰. `battleActive=false`로 전환 후 `.center`는 티르코네일 노드 화면으로 복원.

**6) 재접속**(`GET /`)
- 진행 중 전투(`active`)가 있으면 저장된 몬스터 HP로 battle-view를 그대로 복원하고 `battleActive=true`로 진입한다(§3).

### 6.2 활동 로그 포맷 (사용자 요구 반영)

매 턴 **2줄** 반환. 스킬명·타입·피해, 몬스터 타입·피해를 포함.

- 플레이어: `윈드밀(일반)로 너구리에게 10 피해` — 크리티컬 시 `… 15 피해 (크리티컬!)`, 방어 승 시 `… 방어로 6 피해 (반격)`.
- 몬스터: `너구리의 일반공격, 13 피해를 입음` — 방어 성공 시 `너구리의 일반공격을 방어 (5 피해)`.
- 마법 캐스팅 실패: `파이어볼트 캐스팅 실패!` (형식 `{스킬명} 캐스팅 실패!`, 플레이어 로그 자리 — 이 턴 유저 피해 0).
- 활 1턴 선제: `선제 사격! 너구리에게 12 피해` (몬스터는 이 턴 반격 못 함).
- 도망: 성공 `도망쳤다!` / 실패 `도망 실패! 너구리에게 13 피해`.
- **승리 보상**: 먼저 `alert("너구리가 쓰러졌습니다!")` → 활동 로그 **3줄**(순서 = 골드 → 드랍 아이템 → 경험치):
  - `10골드를 획득하였습니다.` (goldDrop 6~16 중)
  - `생명력 30 포션을 획득하였습니다.` (드랍 성공 시에만, 형식 `{아이템명}을(를) 획득하였습니다.`)
  - `22 경험치를 획득하였습니다.` (`monster.experience`)
- 드랍 초과: `초보자용 한손검 획득 실패!`.
- 내구도 파손: `초보자용 한손검 내구도 0 — 장착 해제됨`.
- 사망: `쓰러졌다… 티르코네일에서 부활 (경험치 -N)`.
- 타입 CSS class는 기존 `combat` 사용(`action-log.html`이 `log-<type>`로 렌더).

> `ActionLog`는 최대 10건(초과 시 오래된 것 제거)이므로, 한 턴 2줄 기록이 로그를 빠르게 채운다 — 표시 정책 유지(문제되면 후속 조정).

## 8. 테스트 계획

`code-style` 기준(JUnit5, jqwik property, `@WebMvcTest`는 `spring-boot-starter-webmvc-test` + `WebMvcTest`(신 패키지), `@MockitoBean`).

- `BattleResolver` (순수, jqwik property):
  - 9칸 매트릭스 각 케이스의 피해 산출 검증(상성 승/무/방어/관통).
  - 감산형 공식(공격력×배율−방어), **최소 데미지 1 보장**, 크리티컬 1.5배(모든 결과 적용).
  - 방어 승: 공격자 데미지 `(1−blockRate)` 경감·반격 발생. 동일 타입: 양쪽 50%. 방어끼리: 0.
- 선후공: 동일 타입 50:50 분포(시드 고정), 선공 처치 시 후공 피해 0, **일반↔방어는 결정론적(공격자 경감뎀 → 반격 순서)**.
- 자원 부족: 비용 미달 스킬은 턴 미진행(자원 차감·데미지 없음).
- 데미지 편차: 시드 고정 `Random`으로 최종 데미지가 보정값의 **90~110% 범위** 내, 최소 1 유지.
- 재능 특성(§2.7): 활 1턴 선제(첫 턴 몬스터 0·유저 100%, 방어 스킬도 반격 100%) + 2턴차 일반 규칙 복귀; 마법 캐스팅 실패 10% 분포·실패 시 MP 소모·방어 예외·몬스터 방어면 양쪽 0; 자원 종류별 소모(스태미나/MP).
- `CharacterProgress.damageHp`: 0 바닥, `isDead` 전이 (property).
- `BattleService`: 턴 처리 통합(스킬 사용/막타 카운트 호출, 내구도 0.2 감소, saveTurn 호출 — Mockito verify).
- `InventoryService.acquire`: 골드 가산·아이템 적재, 용량 초과 시 소실+`획득 실패` 로그.
- 도망: 50% 분포(시드 고정), 실패 시 몬스터 1회 피격·전투 유지, 성공 시 종료.
- 사망: HP 0 → 경험치 −10% + 풀 회복 + 티르코네일 리스폰 + 골드/아이템 불변.
- 내구도 0: `reduceDurability`로 0 도달 시 자동 장착 해제.
- 전투 스킬 노출: 착용 무기 재능 스킬 + 공통 스킬만 반환(무기별).
- `BattleState` 영속/재개: 매 턴 저장 후 재조회 시 몬스터 HP 보존, `GET /` 재접속 시 전투 복원 (repository + 컨트롤러 테스트).
- `BattleController`: `/battle/start`, `/battle/turn`, `/battle/flee`, `GET /battle/skills`(무기 재능 스킬+공통 재렌더) 프래그먼트/로그 응답 (`@WebMvcTest` + `@MockitoBean`).
- 회귀: 임시 개발용 버튼(골드/경험치/승급 드라이버) 제거 후 기존 컨트롤러 테스트 정리(제거된 엔드포인트 참조 테스트 삭제).
